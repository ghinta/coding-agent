Architecture evaluation · confidential software engineering

Enterprise coding agents without giving up control of code, tools, or state.

The project defines an agentic coding platform for confidential repositories and internal systems. The preferred architecture keeps the complete agent harness on-premises and treats the external LLM as a replaceable, stateless inference service.

Project thesis

A production coding agent is not an LLM with shell access. It is a controlled software system around the model: context selection, workflow state, tool contracts, policy, memory, validation, observability, recovery and human control. The model is one replaceable component inside that harness.

Brain

LLM

Interprets goals, plans steps, chooses tools and synthesizes results. It never owns internal credentials.

Control plane

Orchestrator

LangGraph manages state, conditional routing, parallelism, retries, checkpoints, pauses and resumable execution.

Capabilities

Tools via MCP

Narrow, typed interfaces expose GitLab, CI/CD, OpenShift, databases and internal APIs.

Continuity

Memory

Short-term state, semantic code context, episodic feedback and procedural conventions live outside the model.

Trust

Supervisor + verifier

A supervisor delegates work; an independent verifier checks evidence and invariants before results or writes are accepted.

Safety

Policy + HITL

Deterministic rules remain authoritative. Sensitive actions can pause for human approval.

Preferred reference architecture

Variant A keeps the agent runtime on-premises and sends only deliberately selected context to an external inference provider. The LLM Gateway is the single egress path; internal systems are reached locally through MCP and policy enforcement.

Multi-agent model

Multiple agents are useful only when they separate responsibilities, context, tools or permissions. For coding workflows, the current design favors a supervisor pattern over an uncontrolled swarm because validation matters more than minimizing handoffs.

Code AgentRepository analysis and implementation.
Test AgentTest execution, failure analysis and edge cases.
Security AgentAdversarial review and security findings.
Control hierarchy

Supervisor → Specialists → Verifier

Specialists can fan out in parallel. Findings are merged, deduplicated and checked by an independent verifier before they reach the developer or trigger a write action.

Where agentic workflows pay off

The target is not just “chat with the codebase.” The platform is most valuable when work needs state, multiple tools, branching, retries, parallel specialists, verification and controlled approval.

Engineering

Feature implementation

Analyze repository → plan → modify → test → static/security checks → correct → verify.

Review

Selective PR review

Parallel security, quality, testing and documentation review with evidence, deduplication and final verification.

CI/CD

Failure investigation

Classify failure → inspect logs → propose fix → apply in sandbox → rerun → repeat when needed.

Security

Vulnerability triage

Determine reachability and project relevance before creating and validating remediation.

Operations

Incident investigation

Observe → hypothesize → diagnose → approve risky action → remediate → verify → document.

Data

Controlled data workflows

Inspect schema → build validated read-only query → execute → refine → answer with evidence.

Security and production invariants

Model output is treated as untrusted input. Deterministic software controls what the agent may see, call, change and persist.

Tool design

Narrow and typed

Prefer scoped functions such as read_repository_file(project_id, path), run_tests(project_id) and get_pod_logs(namespace, pod). Arbitrary shell, raw SQL and unrestricted SSH are excluded by default.

Validation

Pydantic strict schemas

Structured model output that drives downstream logic must pass explicit type and business validation before it can affect state or tools.

Autonomy

Bounded loops

Hard limits on hops, tokens, time and cost. Retries use circuit breakers and idempotency to prevent uncontrolled execution.

Writes

Human-in-the-loop

Reads can be automatic. Merge requests, production changes, database writes and other sensitive actions can pause for approval.

Execution

Sandboxed code and tests

Generated code executes in ephemeral, network-restricted environments rather than on shared production hosts.

Observability

Self-hosted event spine

Trace retrieval, tool calls, model usage, latency, cost and state transitions without sending full sensitive traces to a SaaS system.

Context and quality engineering

Better models do not compensate for weak context. Repository rules, architectural decisions, tool descriptions and acceptance criteria are first-class engineering artifacts.

Context minimization

Retrieve the smallest relevant code and procedural context instead of sending whole repositories.

Versioned instructions

System prompts, tool docstrings, project conventions and ADRs are reviewed and versioned like code.

Evidence over claims

“Tests pass” is only accepted when the platform actually reruns authorized verification.

Selectivity over noise

Code review should optimize for high-confidence, high-value findings rather than comment volume.

Code-based evals first

Use deterministic tests wherever ground truth exists; use model judging only for genuinely open-ended quality dimensions.

Framework abstraction

Keep orchestration behind Run / Resume / GetState-style interfaces so LangGraph is replaceable if requirements change.

Proposed implementation path

Increase autonomy only after evidence, observability and policy controls are proven.

Phase 0

Architecture and contracts

Finalize provider requirements, data classes, trust boundaries, tool contracts, identity model and ownership.

Phase 1

Read-only coding assistant

Repository inspection, search, CI/log analysis and internal knowledge access. No write-capable tools.

Phase 2

Verified engineering workflows

Feature planning, sandboxed code changes, tests, selective PR review, verifier and complete tracing.

Phase 3

Controlled write actions

Feature branches and merge-request creation behind OPA policies, approval gates and project-level RBAC.

Phase 4

Scale and provider resilience

Fallback providers, budgets, parallel workers, eval suites and continuous feedback into episodic memory.
